# Thesis evaluation packet

This packet supports an honest system evaluation. It supplies tasks and recording fields; it does not contain invented participant results, official PACUCOA ratings, or synthetic performance claims.

## System evidence to retain

- Architecture: React/Vite browser client, Nginx reverse proxy, Django/DRF/Gunicorn application, PostgreSQL, and protected evidence storage.
- Role matrix: Administrator, Coordinator, Reviewer, Custodian, and Viewer, with scoped grants and default-deny access.
- Workflow: evidence upload/version, mapping, independent review, Coordinator certification, dashboard/report status, audit record, and closed-cycle protection.
- Screenshots: login, dashboard, requirement/detail, evidence history, review decision, certification, report, audit filter, cycle lifecycle control, and mobile navigation. Label all seeded examples as fictional.
- Acceptance record: test commands/results, release checklist, backup archive identifier, and separate-environment restore rehearsal record.

## Comparable participant tasks

Use the same fictional requirement and evidence for the baseline process and the Hub. Do not expose real institutional evidence to evaluators unless approved by the school.

| Task | Start | Success condition | Measure |
|---|---|---|---|
| Retrieve an approved document | Task prompt shown | Correct pinned version downloaded by an authorized role | Elapsed time; success/failure; errors |
| Identify missing work | Task prompt shown | Participant identifies the specified missing requirement from the scoped dashboard/report | Elapsed time; success/failure; navigation steps |
| Submit and review evidence | Fictitious file supplied | Custodian submits; independent Reviewer records a justified decision | Completion rate; validation errors; review turnaround |
| Certify readiness | Approved fictional evidence supplied | Coordinator records rationale-backed completion and confirms dashboard change | Completion rate; elapsed time; misunderstanding notes |
